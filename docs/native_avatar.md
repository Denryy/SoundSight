# Собственный 3D жестовый аватар (native avatar)

SoundSight умеет показывать жестовый перевод двумя движками: внешним **CWASA**
(SiGML, vhg.cmp.uea.ac.uk — чужие модели и чужой формат) и **собственным
3D-аватаром**, описанным здесь. Свой аватар — это полностью наш стек: свой
формат поз, свой процедурный гуманоид на three.js, свой лексикон жестов,
редактор и захват жестов из видео. Никаких внешних скриптов и моделей,
работает офлайн, расширяется без чьих-либо разрешений. Вдохновение —
SignAvatars (ECCV 2024), но реализация словарная и честно более простая;
путь к генеративной модели описан в `ml/README.md`.

## Поток данных, от речи до жеста

```
речь → Whisper ASR → агент-фильтр → avatar/sync.sync_chunk()
                                        │
                     avatar/synthesis.synthesize(text)
                       ├─ SiGML (для CWASA)            ← как раньше
                       └─ avatar/pose_synthesis.build_pose_track(text)  ← НОВОЕ
                                        │
            WS-payload final: { avatar_sigml, avatar_pose, ... }
                                        │
        frontend: integration/avatarEngine.playFinal(msg)   ← шина движков
                       ├─ engine = "cwasa"  → cwasa.play(avatar_sigml)
                       └─ engine = "native" → nativeAvatar.play(avatar_pose)
                                                  │
                              avatar3d/player.ts: трек → ключевые кадры →
                              лерп каналов → humanoid.applyChannels()
```

Оба представления (SiGML и pose-track) синтезируются на каждый финальный
сегмент параллельно, поэтому переключение движков в UI мгновенное и не
требует перезапуска сессии.

## Формат поз — единый контракт

Канонічное описание: `frontend-react/src/avatar3d/poseTypes.ts` (типы +
комментарии) — его же придерживаются `avatar/native_lexicon.json`,
«Аватар-лаб» и `ml/extract_pose_clip.py`. Кратко:

— Все углы в **градусах**, семантика анатомическая и одинакова для обеих рук
  (зеркалит знаки сам гуманоид): `sh:[подъём, в-сторону, вращение]`, `el`
  локоть, `tw` вращение предплечья (+супинация), `wr:[сгиб, отклонение]`;
  пальцы — `curl` (число-шорткат или `[mcp,pip,dip]`) и `spread`; большой —
  `spread/oppose/curl`; `head`, `spine` — тройки.
— Позы **частичные**: незаданный сустав наследуется от предыдущего ключевого
  кадра клипа, а в начале — от базовой позы. Это держит JSON компактным.
— Клип глосса: `{ru?, aliases?, hold?, frames:[{t_мс, pose}]}`.
— Трек от бэкенда: `{v:1, signs:[ {kind:"gloss",id} |
  {kind:"spell", alphabet:"asl"|"ru", letters:[...]} | {kind:"gap"} ]}` —
  бэкенд решает «что показать», фронтенд знает «как именно» (формы букв и
  тайминги живут в бандле).

## Бэкенд

`avatar/pose_synthesis.py` — роутинг текста в знаки:

1. перевод RU/KZ→EN тем же argostranslate, что и для SiGML;
2. слово ищется в лексиконе (`native_lexicon.json`, id + aliases) **до**
   стоп-фильтра — поэтому «hi/hello» жестикулируются, а не выкидываются;
3. не найдено — дактиль: латиница → ASL-алфавит, кириллица → русский дактиль;
4. между словами вставляется `gap`;
5. лимиты те же, что у SiGML: `AVATAR_MAX_WORDS`, `AVATAR_MAX_LETTERS`.

Режимы через `SIGN_LANG` (core/config.py): `hybrid`/`asl`/`isl` ведут себя
как раньше, новый **`ru_dactyl`** дактилирует кириллицу напрямую без перевода.
Бонус нативного движка: если перевод недоступен (нет моделей argos), кириллица
автоматически уходит в русский дактиль — CWASA в этой ситуации молчал.

HTTP: `GET /avatar/native/lexicon` — лексикон целиком (его тянет фронтенд,
единый источник правды); `GET /avatar/native/pose?text=...` — трек для
отладки. Поле `pose` добавлено и в `/avatar/preview`.

Тесты: `tests/test_native_avatar.py` (роутинг, алиасы, лимиты, режимы,
валидность лексикона, интеграция с synthesize, кириллический фолбэк).

## Фронтенд (`frontend-react/src/avatar3d/`)

— **humanoid.ts** — процедурный гуманоид из капсул: иерархия плечо(3 оси) →
  локоть → твист → кисть(2 оси) → 5 пальцев с фалангами. Никаких загружаемых
  моделей — собирается кодом, красится переменными темы.
— **poses.ts** — поза покоя, фингерспеллинг-стойка, **ASL A–Z** и
  **русский дактиль А–Я** как `LetterDef` (статичная поза или мини-клип для
  букв с движением вроде J/Z/Й). Формы — стартовое приближение, см. ниже.
— **player.ts** — `NativeAvatarController`: очередь треков (макс. 8, как у
  CWASA), таймлайн ключевых кадров с лерпом каналов, idle-дыхание, возврат в
  покой. Экспортирует синглтон `nativeAvatar` для экрана «Субтитры» и класс —
  для собственных сцен (Аватар-лаб). Рендерит только при видимом контейнере
  (экран «Субтитры» прячется через `display:none` — это учтено).
— **integration/avatarEngine.ts** — шина: хранит выбор движка в
  `localStorage("soundsight.avatarEngine")`, роутит `playFinal`, отражает
  готовность активного движка, чистит очереди при переключении.
  `SessionContext` и панель аватара работают только через неё.

Переключатель «Свой 3D | CWASA» — в панели аватара на экране «Субтитры».
Контейнеры CWASA при этом остаются в DOM (движок теряет canvas при
размонтировании) и только прячутся классом `is-hidden`.

## Аватар-лаб — мастерская жестов

Экран в сайдбаре. Три вкладки:

— **Дактиль** — предпросмотр любой буквы обоих алфавитов и дактилирование
  произвольного слова;
— **Глоссы** — проигрывание клипов лексикона (тянутся с бэкенда);
— **Поза** — слайдеры всех суставов правой руки, пальцев, большого пальца и
  головы; справа живой JSON позы и кнопка «Копировать».

### Как добавить новый жест (рабочий цикл)

1. Во вкладке «Поза» соберите ключевые положения жеста слайдерами, копируя
   JSON каждого (это кадры `pose`).
2. В `avatar/native_lexicon.json` добавьте глосс: id латиницей, `ru`-метку,
   `aliases` (формы слова, по которым он ищется), `frames` с таймингами `t`
   в мс и `hold`.
3. Перезапустите бэкенд (лексикон читается при импорте) — жест появится во
   вкладке «Глоссы» и сразу начнёт срабатывать в живых субтитрах.
4. Либо быстрее: запишите жест на видео и `ml/extract_pose_clip.py --merge`
   (см. `ml/README.md`) — а в Лабе только доведите детали.

## Скиновая 3D-модель (Mixamo / Blender → glTF)

Помимо процедурного тела, аватар умеет надевать **готовую скиновую модель** —
ту же артикуляцию каналов получает настоящий 3D-персонаж. Сейчас подключён
`frontend-react/public/models/connor.glb` (риг Mixamo). Подмена бесшовная:
модель грузится в фоне, до готовности (или при любой ошибке) играет
процедурный человечек — аватар не пропадает никогда.

### Как это устроено: драйвер-скелет + ретаргет по дельте

Мы НЕ сопоставляем каналы локальным осям костей вручную (хрупко: оси костей
Mixamo произвольно скручены вдоль кости). Вместо этого процедурный `Humanoid`
работает **невидимым драйвером**: его суставы крутятся по уже проверенной
канальной математике, а `skinnedHumanoid.ts` переносит их **мировые** повороты
на одноимённые кости модели по дельте:

```
target_world(кость) = Δ_драйвера · rest_world(кость),   Δ = q_now · q_bind⁻¹
q_local(кость)      = q_родителя⁻¹ · target_world
```

Это корректно при любой ориентации rest-фрейма и любом «roll» кости — нужно
лишь, чтобы на момент *bind* драйвер и модель были в одной физической позе.
Rest-поза Mixamo — это **A-поза** (руки опущены и разведены ~44°), поэтому
драйвер связывается в той же позе (`MIXAMO_BIND` в `mixamoRig.ts`, значения
вычислены анатомическим ретаргетом из rest-скелета модели). Для пальцев
дополнительно выравниваем плоскость сгиба по ладони модели (`align·Δ·align⁻¹`),
иначе при разной ориентации ладоней пальцы гнулись бы вбок. Алгебра ретаргета
покрыта оффлайн-проверкой (см. ниже).

Файлы: `avatar3d/skinnedHumanoid.ts` (адаптер, тот же интерфейс
`{root, applyChannels}`, что у `Humanoid` — поэтому плеер их взаимозаменяет),
`avatar3d/mixamoRig.ts` (соответствие костей, bind-поза, нормализация имён),
`Humanoid.driverSegments()` (отдаёт суставы драйвера под именами костей Mixamo).

### Подключить свою модель

1. Подготовьте риг в Blender/Mixamo: **обязательны кости пальцев** (по 3 фаланги
   + большой), иначе дактиль невозможен. Экспорт glTF 2.0 (`.glb`), Apply
   Transforms, метры или сантиметры — масштаб подгоняется автоматически.
2. Положите файл в `frontend-react/public/models/` и укажите путь в
   `SKINNED_MODEL_URL` (player.ts). Путь `/models/...` намеренно вне API-префикса
   `/avatar`, чтобы не конфликтовать с роутами бэкенда.
3. Если кости названы по стандарту Mixamo (`mixamorig:RightForeArm` и т.п.) —
   заработает сразу. Иначе поправьте `cleanMixamoName`/`BONE_MAP` под именование
   вашего рига (а для VRM-моделей маппинг костей стандартизован — можно сделать
   аналогичный `vrmRig.ts`).
4. Если rest-поза модели — **T-поза**, а не A-поза, обновите `MIXAMO_BIND`
   (для чистой T-позы: `sh:[0, 90, 0], el:0`).

### Проверка ретаргета без браузера

`node /tmp/retarget_test.mjs` (скрипт в репозитории — `ml/retarget_test.mjs`)
проверяет кватернионную алгебру переноса: что `Δ = q_now·q_bind⁻¹`, что мировой
поворот кости выходит `Δ·rest`, и что выравнивание сохраняет сгиб пальца в
системе ладони модели. Это ловит ошибки знаков/порядка умножений, но НЕ заменяет
визуальную проверку.

— Формы букв и жестов в `poses.ts`/`native_lexicon.json` — **приближение,
  сделанное по описаниям**, не выверенное носителями ЖЯ. Перед показом
  глухой аудитории их обязательно нужно проверить со специалистом по РЖЯ/КРЖЯ
  и поправить в Лабе — инфраструктура для этого и построена.
— Дактиль — это побуквенная азбука, а не жестовый язык; лексикон из ~10
  глоссов покрывает только частые слова. Это словарная ступень, не перевод.
— Тело гуманоида процедурное и стилизованное: без мимики и артикуляции рта,
  которые в настоящих ЖЯ несут грамматику.
— Захват из видео надёжен для плеча/локтя/сгибов пальцев; вращения (`tw`,
  `sh[2]`) и кисть из монокулярного видео приблизительны.
— **Скиновая модель проверена только сборкой и оффлайн-тестом алгебры
  ретаргета — не рендером в браузере.** Самый вероятный кандидат на доводку —
  направление сгиба пальцев (зависит от ориентации ладони модели в bind) и
  кадрирование/масштаб. Запустите `npm run dev`, посмотрите глазами, при
  необходимости подправьте `MIXAMO_BIND` и `TARGET_HEIGHT`. Формы букв, как и у
  процедурного аватара, доводятся в «Аватар-лабе» — они общие для обоих тел.

## Куда расти

Генеративный путь (корпуса FluentSigners-50/Slovo → VQ-VAE движения →
трансформер «глоссы → движение», как в SignAvatars) расписан в
`ml/README.md`. Формат `avatar_pose` спроектирован так, что замена словарного
роутинга на модель не потребует менять фронтенд.
